# 本地 AI 助手

这个分支为 DyberPet 增加了一个**开源、离线优先**的助手。它和上游尚未开源的云端 LLM 模块是两套独立实现：这里的所有代码都在 `DyberPet/LLM/` 中，不依赖任何私有服务。

核心原则：

- **不装模型也能用。** 内置回答直接读取桌宠、任务和专注数据，覆盖状态、待办、进度、金币、建议等常见问题，还能直接添加、完成、删除待办。
- **模型是可选项。** 只有用户主动开启，并且地址是本机回环地址时，才会请求本地模型；请求失败时保留内置回答，不会出现空白回复。
- **数据不出本机。** 不发送账号、文件路径、任务 ID 或系统信息；只发送宠物、待办和专注的摘要。不支持 API Key，也不跟随重定向，详见下文。

## 打开助手

在桌宠上右键 → **AI 助手**（`AI Assistant`）。窗口里可以：

- 直接输入问题，按 Enter 或点“发送”。
- 点击“任务 / 进度 / 宠物”快捷按钮。
- 点击“设置”选择是否启用本地模型。
- 点击“清空”重新开始对话（聊天记录只保存在当前窗口内，关闭窗口后不落盘）。

## 不接模型时的内置能力

内置回答支持中文和英文，会识别问题的语言并回答。数字全部来自当前存档，不会编造。

| 意图 | 示例 | 说明 |
|---|---|---|
| 状态 | `你好` / `how are you?` | 饱食度、好感度、金币、陪伴天数 |
| 任务列表 | `查看任务` / `show my tasks` | 按 1、2、3 编号列出待办 |
| 添加任务 | `帮我添加任务：写周报` / `add task write the report` | 也识别 `remind me to …`、`todo: …` |
| 完成任务 | `完成 2` / `complete 2`、`写报告完成了` | 按编号、完整文本或部分文本匹配 |
| 删除任务 | `删除任务 买牛奶` / `delete task buy milk` | 只删除待办，不动已完成列表 |
| 进度 | `今天进度怎么样？` / `how is my progress?` | 今日专注分钟、目标、连续天数 |
| 金币 | `我有多少金币？` / `how many coins do I have?` | 当前金币数与累计完成任务数 |
| 总结 | `总结一下今天` / `summarise my day` | 进度、任务、宠物状态的一段汇总 |
| 建议 | `我该做什么？` / `what should I do?` | 按“饿了 → 任务 → 专注”的优先级给建议 |
| 帮助 | `你能做什么？` / `what can you do?` | 能力与示例 |

任务操作和帮助类问题**始终由内置逻辑处理**，不会交给模型，避免模型误删或误加任务。

## 接入本地模型（可选）

助手使用 OpenAI 兼容的 `/v1/chat/completions` 接口，支持：

| 服务 | 默认地址 |
|---|---|
| [Ollama](https://ollama.com/) | `http://127.0.0.1:11434/v1` |
| [LM Studio](https://lmstudio.ai/) | `http://127.0.0.1:1234/v1` |
| llama.cpp server | `http://127.0.0.1:8080/v1` |

### 1. 安装并启动服务

以 Ollama 为例：

```sh
ollama pull qwen3:1.7b
ollama serve
```

Windows 安装版 Ollama 通常已在后台运行，不需要手动 `serve`。

### 2. 在助手设置中连接

1. 点击助手窗口右上角“设置”。
2. 勾选“有可用本地模型时使用”。
3. 选择服务，或填写自定义回环地址。
4. 点击“检查”，从下拉框选择模型。
5. 保存。

设置会写入 `data/settings.json` 的 `llm_enabled`、`llm_base_url`、`llm_model` 三个字段。关闭助手窗口不会丢失。

### 3. 模型大小建议

以下为 Q4_K_M 量化、约 2K 上下文的粗略占用，实际取决于上下文长度和服务实现：

| 模型 | 显存/内存 | 适用 |
|---|---|---|
| Qwen3 0.6B | 约 0.7–1.0 GB | 最低可用，短回答 |
| Qwen3 1.7B | 约 1.5–1.9 GB | **推荐**，速度与质量平衡 |
| Qwen3 4B | 约 3.5–4 GB | 更自然，速度较慢 |
| 0.3B 级别 | < 0.5 GB | 不建议，容易答非所问 |

显存充足时可以用 4B 或更大模型；只有核显/集显时建议 0.6B–1.7B。Qwen3 系列会自动附加 `/no_think` 并预留 700 个生成 token，避免思考过程把回答挤成空字符串。

### 4. 模型回答如何使用内置答案

每次请求都会把内置回答作为 `REFERENCE ANSWER` 一并发送，并要求模型：

- 保留其中的事实和数字，不得矛盾；
- 不计算新的消耗速度或未来用量；
- 用更自然的语气重述，可以补充通用建议。

模型成功返回后，界面会用模型回答替换内置回答，并标注“本地 · 模型名”；失败时保留内置回答，只把错误显示在状态栏。

## 隐私与安全边界

- 只接受 `localhost`、`127.0.0.1`、`::1` 三种主机名，端口任意；`http` 和 `https` 均可。
- 拒绝带用户名/密码、查询参数、片段、空白或控制字符的地址。
- 使用标准库 `urllib`，禁用所有重定向；响应体不会写日志，也不会显示在错误信息里。
- 不发送 `Authorization` 或其他凭据；本功能没有 API Key 输入框。
- 请求上限：问题 500 字符、上下文 12,000 字符、参考回答 4,000 字符、回答 4,000 字符；模型列表最多 60 个。
- 响应上限：模型列表 256 KiB、对话 128 KiB；同时检查 `Content-Length` 和分块读取总量。
- 发送给模型的上下文仅包含：宠物名、饱食度/好感度/金币/陪伴天数、待办文本（最多 20 条）、已完成数量、今日专注/目标/连续天数、最近 6 条聊天（每条最多 400 字符）。**不包含**任务 ID、文件路径、账号、物品、系统信息。
- 上下文被明确标注为不可信数据，系统提示要求模型忽略其中出现的指令。

## 实现结构

```
DyberPet/LLM/
├── __init__.py          # 只导出纯逻辑，导入它不会加载 Qt
├── assistant.py         # 纯函数：意图识别、回答、上下文、任务匹配
├── local_client.py      # 纯标准库：回环 URL 校验、探测、请求、响应清洗
├── runtime.py           # 读写 settings/task_data，执行任务动作
├── chat_window.py       # 聊天窗口、后台线程、内置/模型结果切换
└── settings_dialog.py   # 启用开关、服务、地址、检查、模型选择
```

设计约束：

- `assistant.py` 与 `local_client.py` 不导入 Qt，可以在无 GUI 环境直接测试。
- `runtime.py` 只在执行动作时接触游戏存档；模型请求线程不碰 UI。
- 模型调用使用守护线程，退出应用时不会留下无法销毁的 `QThread`。
- 设置保存失败时不会悄悄改用内存配置，而是提示用户。

## 测试

```sh
python -m unittest discover -s tests -v
```

覆盖内置意图、中英文解析、任务查找、上下文裁剪与隐私、URL 校验、重定向拒绝、无凭据请求、Qwen3 token 预留、思考内容剥离，以及运行时任务动作（含第 5 个任务的额外奖励）。

不启动 GUI 的模块编译检查：

```sh
python -m py_compile DyberPet/LLM/*.py
```

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 设置里“检查”提示没有服务 | 先启动 Ollama / LM Studio / llama.cpp；确认端口与地址一致 |
| 提示“服务未启动”但服务在运行 | 地址必须是 `127.0.0.1`、`localhost` 或 `::1`，不能是局域网 IP |
| 有模型但下拉框为空 | 服务返回的模型列表为空，先在服务里 `pull` / 下载模型 |
| 回答很慢 | 首次加载模型需要时间；换更小模型或减少上下文长度 |
| 模型回答为空 | 已自动回退内置回答；检查服务是否支持 `max_tokens`，或换 1.7B 以上模型 |
| 关闭窗口后对话消失 | 设计如此：聊天记录只在窗口生命周期内保存 |
| 修改设置后没生效 | 保存后立即生效；配置文件被外部改动则需重启应用 |

## 与上游的关系

上游 README 说明其云端 LLM 模块尚未完全开源。本分支没有复制、反编译或依赖那部分代码，而是在 `DyberPet/LLM/` 中独立实现了离线助手和可选的本地模型桥接。许可证仍为 GPL-3.0，与仓库一致。
